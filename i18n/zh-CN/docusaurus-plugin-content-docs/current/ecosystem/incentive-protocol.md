# 激励协议

激励协议是一套围绕 MINI 建立的生态激励基础设施。

它为生态项目创建独立市场，让用户通过持有、质押和交易表达支持；同时根据市场表现分配 MINI，为项目提供流动性、建设者收益和长期激励。

## 生态激励的基础设施

MINI 承载 JAM 生态启动、Polkadot 生态激励和 MiniJAM 生态建设之间的价值流通。这些价值最终需要进入具体的建设活动，包括：

- 网络和基础设施开发；
- 面向用户的产品与应用；
- 开发工具和公共服务；
- 流动性和市场建设；
- 真实用户的参与和使用；
- 无法依靠商业收入维持的公共物品。

传统生态激励通常通过拨款、委员会审批或一次性分发完成。在某些时期，它们对生态的发展起到了非常大的推动作用，但弊端也非常明显。建设者面对是委员会或治理机制，并未真正面向用户。即便是面向社区治理的二元拨款机制，并无法表达市场偏好的多样性。最终，带来劣币驱逐良币的结果。

激励协议提供另一种路径：

```
建设者创建项目
        ↓
项目建立公开市场
        ↓
用户购买、持有和质押 Alpha
        ↓
市场形成价格与流动性
        ↓
MINI 根据市场结果进入项目
        ↓
建设者、用户和公共物品获得激励
```

在这种结构中，用户通过真实资金和市场行为表达判断，建设者可以直接面向用户获得启动资源和长期收益。未来我们希望这种协议作为一种常规的早期创新项目的资本市场。

## 激励协议

激励协议为每个项目建立独立的 **Alpha 市场**。Alpha 是项目自身的市场资产。它承载用户对项目的支持，也用于建立流动性、参与质押、分配项目奖励和生成公共物品投票额度。

基础机制可以概括为五个部分：

```
建立项目市场
      ↓
持有并质押 Alpha
      ↓
根据市场表现排放
      ↓
用户或项目可以退出
      ↓
将部分影响力用于公共物品
```

### 建立项目市场

每个项目首先创建独立的 Alpha。完成 Alpha Genesis 后，项目进入市场上线阶段：

1. 上线控制者提供一定数量的 vMINI；
2. 协议释放预留用于流动性的 Alpha；
3. vMINI 与 Alpha 共同建立流动性池；
4. 用户可以购买、出售 Alpha，或向市场提供额外流动性。

### 质押并支持项目

用户可以购买、持有项目 Alpha，也可以将 Alpha 质押到项目对应的 Staking Vault。质押表示用户愿意在一段时间内承担项目相关的市场风险，并将自身利益与项目的长期发展绑定。质押者将获得协议 mint 的 **Alpha。**

### 按市场表现排放

激励协议按 Epoch 向项目分配排放预算，分配比例取决于项目的市场表现。简单来说，使用上一个 Epoch 的价格 EMA，并设置价格上限。

排放的 MINI 将以三种方式分配：

- **增加市场流动性**：协议将项目获得的 vMINI 注入流动性池，同时按照当前池内储备比例铸造配套 Alpha：vMINI 与 Alpha 按照现有价格比例同时注入，从而在增加流动性时尽量保持池内价格连续。
- **分配 Owner Alpha**：协议按照预先配置的比例铸造 Alpha，并发送到项目的 Owner 排放接收地址。这部分用于让项目所有者或核心建设者分享项目发展形成的长期价值。
- **奖励 Alpha 质押者**：另一部分 Alpha 发送到项目的 Staking Vault，再按照有效质押量分配给质押者。

### 支持公共物品

部分生态贡献无法通过发行独立 Alpha 或建立商业市场获得收入，例如：

- 开源工具；
- 公共 RPC；
- 教育和文档；
- 社区基础设施；
- 通用开发组件；
- 其他公共服务。

激励协议允许 Alpha 质押者将自身形成的影响力分配给公共物品。当前公共物品投票额度同时取决于：

- 用户在某个项目中的有效 Alpha 质押量；
- 该项目上一 Epoch 的 Alpha 价格 EMA。

用户可以将投票额度分配给不同公共物品。公共物品按照获得额度占总额度的比例，分享当期公共物品 vMINI 排放。

## 子协议

上述基础机制可以让一个已经拥有 Alpha 和初始流动性的项目进入市场并获得持续排放。但对于极早期项目，建立初始市场本身就是困难的。

不同项目也适合不同机制。有的项目适合绑定曲线，有的适合拍卖；有的需要按产品使用量激励用户，有的需要根据建设里程碑释放资金；有的希望把大部分手续费留给建设团队，有的则希望持续奖励用户和公共物品。

激励协议实际上并不真正面向项目和用户，我们甚至不会建立前端。真正面向用户的是子协议，它决定项目如何进入激励市场，以及启动、流动性、排放和 Owner 权益如何分配。因此，子协议可以非常灵活、高效地实现各种机制。例如：

- 严格的人工审查机制；
- 采用 AI 来验收结果；
- 建立验证者和 Worker 网络；

### 市场启动

市场启动负责将一个早期项目带入 Alpha/MINI 市场。子协议可以决定：

- 用户如何参与；
- Alpha 如何发行和分配；
- 项目如何获得启动资金；
- 启动成功需要满足什么条件；
- 启动失败后如何退款；
- 多少 MINI 和 Alpha 用于建立流动性；
- 初始价格和 LP 份额如何确定。

项目完成启动后，子协议将准备好的 MINI 和 Alpha 交给激励协议，由激励协议创建并运行流动性市场。不同子协议可以采用绑定曲线、固定价格、拍卖、众筹或其他启动方式。

### 排放

子协议可以定义 MINI 和 Alpha 如何持续分配，包括：

- 分配给建设者、用户或流动性提供者；
- 根据市场价格、产品使用量或建设成果计算；
- 排放持续多久；
- 何时减少、暂停或停止排放。

激励协议负责执行预算和结算，子协议负责定义具体规则。

### Owner 份额

Owner 份额用于定义项目所有者或核心建设者的长期权益。

子协议可以决定：

- Owner 获得多少启动资金；
- Owner 获得多少 Alpha；
- 是否分享持续排放和交易手续费；
- 是否设置归属期或建设里程碑；
- 项目退出时如何处理 Owner 权益。

通过 Owner 份额，建设者可以同时获得早期开发资源和项目长期运行产生的收益。
